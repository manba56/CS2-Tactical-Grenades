# CS2 Tactics Suite — 测试计划

## 1. 测试目标

确保 CS2 Tactics Suite（战术百科网站）的功能、性能、安全性满足上线标准，API 响应正确，前端用户体验流畅，数据安全合规。

## 2. 测试范围

| 范围 | 包含 | 不包含 |
|------|------|--------|
| API 后端 | 全部 32 个 HTTP 端点 | 第三方服务集成 |
| 前端 (cs2-web) | 首页、地图详情、战术详情、收藏、搜索、分页 | — |
| 管理后台 (cs2-admin) | 登录、战术/地图/点位/线路 CRUD、截图上传 | — |
| 性能 | 负载/压力/稳定性测试 | CDN/网络层性能 |
| 安全 | 密码哈希、Token 哈希、上传限制、权限控制、限流 | 渗透测试 |
| 数据 | SQLite 读写一致性、迁移验证 | — |

## 3. 测试策略（金字塔模型）

```
         ┌──────────┐
         │  E2E 测试 │  ~17 用例 (Playwright)
         ├──────────┤
         │  API 测试 │  ~45 用例 (pytest + requests)
         ├──────────┤
         │ 单元测试  │  ~67 用例 (纯函数)
         └──────────┘
```

| 层级 | 工具 | 数量 | 覆盖目标 |
|------|------|------|---------|
| 单元测试 | pytest | 67 | auth/rate_limit/schemas 纯函数 100% |
| 接口测试 | pytest + requests | 45 | 全部 32 个 API 端点 |
| E2E 测试 | Playwright | 17 | 关键用户流程 |
| 性能测试 | JMeter | 3 套场景 | 关键 API 响应时间 |
| 安全测试 | pytest | 10 | 密码/Token/上传/限流/权限 |

## 4. 测试环境

| 环境 | 说明 |
|------|------|
| 本地开发 | Windows 11, Python 3.13, localhost |

## 6. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 限流(429)导致测试误报 | 高 | 中 | 断言接受 429，重试机制 |
| 测试数据残留影响后续运行 | 高 | 中 | TestDataTracker 清理机制 |
| Playwright 浏览器安装失败 | 中 | 高 | Jenkins Dockerfile 预装 |
| JMeter 消耗大量服务器资源 | 中 | 高 | 非 full 级别不跑性能测试 |
| SQLite 并发写入冲突 | 低 | 高 | WAL 模式 |
