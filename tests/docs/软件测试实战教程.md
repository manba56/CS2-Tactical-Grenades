**3.2 自己写一个**

在 `tests/unit/` 下新建 `test_my_unit.py`，测试一个你自己写的函数。比如：

```python
# 自己先写一个被测试的函数
# cs2-api/app/my_module.py

def is_valid_email(email: str) -> bool:
    """简单的邮箱校验"""
    return '@' in email and '.' in email.split('@')[-1]

# 再写测试
# tests/unit/test_my_unit.py

def test_valid_email():
    assert is_valid_email("test@example.com") is True

def test_no_at():
    assert is_valid_email("testexample.com") is False

def test_no_dot_after_at():
    assert is_valid_email("test@examplecom") is False

def test_empty():
    assert is_valid_email("") is False
```

运行：
```bash
python -m pytest unit/test_my_unit.py -v
```

**3.3 练习写断言**

| 断言方法 | 用途 | 示例 |
|---------|------|------|
| `assert x == y` | 等值比较 | `assert result == 200` |
| `assert x is True` | 布尔检查 | `assert verify_password(...) is True` |
| `assert "key" in dict` | 键存在 | `assert "token" in response` |
| `pytest.raises(Error)` | 异常断言 | `with pytest.raises(ValidationError): ...` |

```python
import allure
from playwright.sync_api import Page

@allure.feature("E2E — 首页浏览")
class TestHomePage:

    def test_homepage_loads(self, page: Page):
        page.goto("http://127.0.0.1:5174")
        page.wait_for_load_state("networkidle")
        # 页面标题包含 Tactics
        assert "Tactics" in page.title()

    def test_navigate_to_maps(self, page: Page):
        page.goto("http://127.0.0.1:5174")
        page.click("text=地图库")
        page.wait_for_url("**/maps")
        assert "/maps" in page.url
```

## 面试常见问题（准备好答案）

**Q: 你用过哪些测试方法？**
A: 单元测试（pytest）、接口测试（requests + pytest）、端到端测试（Playwright）、性能测试（JMeter）、安全测试（SQL注入/密码哈希/权限校验）。

**Q: 你是怎么设计测试用例的？**
A: 先用等价类划分和边界值分析覆盖正常场景和异常场景，再用错误推测法补充安全相关用例（SQL注入、XSS、未授权访问）。每个用例包含前置条件、步骤、预期结果。

**Q: 你用过什么测试工具？**
A: pytest（单元+接口）、Playwright（E2E）、JMeter（性能）、Allure（报告）、Jenkins（CI/CD）、Git（版本管理）、ZenTao（缺陷管理）。

**Q: 遇到的最难 Bug 是什么？**
A: B站视频链接保存后消失的 bug。表面看是前端问题，实际排查发现 API 的 `build_tactic_detail` 手动构造返回字段时漏了 `video_url`，更深层是 SQLite 的 `TABLE_COLUMNS` 映射里也没加这个列。经历从 UI → API → 数据库的三层排查。

**Q: 测试覆盖率多少？**
A: 用 pytest-cov 测量，核心模块覆盖率 80%+。但覆盖率只是参考，更重要的是边界和异常场景的覆盖质量。

**Q: 你怎么做 CI/CD 的？**
A: Jenkins Pipeline 分 9 个阶段——代码拉取、健康检查、单元测试、API测试、E2E测试、覆盖率报告、安全审计、性能测试、生成报告。每次提交自动触发。
